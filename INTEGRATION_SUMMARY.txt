HOW IT WORKS:

Mobile → Backend → Device

1. User taps a device setting in the app
2. App validates input locally
3. App sends HTTP request to backend
4. Backend:
   - Validates input again (Zod)
   - Builds USSD command using UssdCommandBuilder
   - Would send to actual device via SMS/USSD gateway
   - Currently returns mock response (ready for real device)
   - Saves config locally
5. Backend responds with success/error
6. Mobile app shows result in alert/toast
7. Config is displayed on screen

Example flow for setting phone number:

  Mobile App                Backend                  Device
      |                        |                        |
      |-- POST /api/device/config/phone -->|
      |  (08000000000)          |                       |
      |                    Validate input               |
      |                    Build command:              |
      |                    *1234*USER*08000000000*08000000000#
      |                    (Would send via SMS gateway)
      |                    Store in DB/memory          |
      |<-- { success: true, message: "..." } --|
      |
   Show alert: "User phone number saved"

WHAT'S CURRENTLY MOCKED:

The implementation is production-ready but currently returns mock device
responses. To wire up the actual 4First device, you need to:

1. Integrate an SMS/USSD gateway (e.g., AfricasTalking, Twilio)
2. Implement device communication logic in backend
3. Replace mock responses with real device responses
4. Add database persistence for device config (currently in-memory)
5. Implement polling/push for real sensor readings

API ENDPOINTS ADDED:

GET  /api/device/sensor/reading          Get weight reading
POST /api/device/sensor/tare             Calibrate scale
POST /api/device/sensor/minimum-level    Set alert level (1-9)
GET  /api/device/info                    Query device status

POST /api/device/config/phone            Set notification phone
POST /api/device/config/location         Set device location
POST /api/device/config/password         Change device password
POST /api/device/factory-reset           Factory reset device

GET  /api/device/config                  Get saved config
POST /api/device/config                  Save config locally

All endpoints require Bearer token authentication.

VALIDATION IMPLEMENTED:

✅ Phone number
   - Must be 10+ digits
   - Must be local format (no +234 prefix)
   - Example: 08000000000 ✓
   - Invalid: +2348000000000 ✗

✅ Password (device)
   - Must be 1-4 alphanumeric characters
   - Example: abc1 ✓
   - Invalid: abcd1234 ✗

✅ Location
   - Must not be empty
   - Max 100 characters
   - Example: Main Warehouse ✓

✅ Minimum Level
   - Must be integer 1-9
   - No decimals
   - Example: 2 ✓
   - Invalid: 2.5 ✗, 10 ✗, 0 ✗
